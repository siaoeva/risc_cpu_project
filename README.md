# Single-Cycle RISC-V CPU (RV32I)

A **single-cycle RISC-V RV32I CPU** implemented in **SystemVerilog**, verified through **assembly-level simulation in Questa**. This project is intended as a **portfolio-quality RTL design** demonstrating CPU microarchitecture, control logic, and verification practices relevant to FPGA and hardware design internship roles.

---

## Project Highlights

- Full single-cycle datapath (CPI = 1)
- Explicit combinational control unit
- Modular RTL design (ALU, regfile, control, branch unit, load unit)
- Verified using hand-written RV32I assembly programs
- Waveform-based correctness validation

---

## ISA Support

**Base ISA:** RV32I  
**Word Size:** 32-bit  
**Endianness:** Little-endian

### Implemented Instructions

**Arithmetic & Logical**  
- R-type: `add`, `sub`, `and`, `or`, `xor`, `sll`, `srl`, `sra`, `slt`, `sltu`
- I-type: `addi`, `andi`, `ori`, `xori`, `slli`, `srli`, `srai`, `slti`, `sltiu`

**Memory**  
- Loads: `lw`, `lh`, `lhu`, `lb`, `lbu`  
- Stores: `sw`, `sh`, `sb`

**Control Flow**  
- Branches: `beq`, `bne`, `blt`, `bge`, `bltu`, `bgeu`  
- Jumps: `jal`, `jalr`

**Upper Immediate**  
- `lui`, `auipc`

## Architecture Overview

The CPU follows a classic **single-cycle RISC datapath** consisting of:

1. Instruction Fetch (PC + instruction memory)
2. Instruction Decode and Register Fetch
3. Execute (ALU + branch comparison)
4. Memory Access
5. Writeback

All control signals are generated by a centralized combinational control unit based on `opcode`, `funct3`, and `funct7`.

## Verification Methodology

Verification is performed in **simulation only**, using **directed RV32I assembly programs** executed on the CPU.

### Test Programs

| Program | Purpose |
|------|--------|
| `sanity.s` | ALU, immediate, and shift instruction verification |
| `load_store.s` | Load/store datapath and sign-extension checks |
| `branch.s` | Branch comparison and PC control verification |
| `jump.s` | `JAL` / `JALR` jump and link behavior |

### Verification Approach

- Instructions are executed sequentially
- Expected architectural behavior is validated via waveform inspection
- Key signals observed include:
  - `pc`, `pc_next`
  - `alu_op`, `alu_result`
  - `reg_write`, `wb_sel`, `wb_data`
  - Register file contents

## Simulation Setup

**Simulator:** Questa

Typical simulation flow:
- File > Change directory > /risc_cpu_project/tb
```text
do testbench.tcl
quit -sim
```

- Assembly programs are assembled using /programs/asm2hex.sh into program.hex prior to simulation
- /tb/wave.do can be edited to include/exclude signals
- /tb/testbench.tcl line 17 can be edited to change runtime
